## Working Principles

- Keep the code **simple, readable, modular, and easy to maintain**. Prefer straightforward solutions over unnecessary abstractions, dependencies, or overengineering.
- Before adding a function, component, service, API, or utility, search the existing codebase and `progress.md` to check whether equivalent functionality already exists. Reuse or extend it instead of duplicating it.
- Make changes in small, testable phases. Avoid implementing the entire project in one large, unverified change.
- After every phase or meaningful update, update `progress.md` with:
  - What was added or changed.
  - New or modified functions, components, APIs, schemas, and files.
  - Existing functionality reused.
  - Tests/checks run and their results.
  - Known issues, limitations, and the next steps.
- Keep `progress.md` accurate and concise. Do not claim something works unless it has been implemented and tested.
- Before starting each new phase, read `progress.md`, inspect the relevant code, and identify what can be reused. Treat the codebase as the source of truth if it differs from the document, then update `progress.md` to reflect reality.
- After changes, run relevant tests, type checks, and builds where available; fix failures before moving on.
- Never add secrets to source control. Keep credentials in environment variables.

## Required Workflow

1. Read `AGENT.md`, `progress.md` (if present), and the relevant existing code.
2. Plan a small, focused change.
3. Implement it using existing utilities and patterns where possible.
4. Test the change and report any checks that could not be run.
5. Update `progress.md` before considering the phase complete.
